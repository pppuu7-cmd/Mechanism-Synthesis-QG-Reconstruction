# Toller causal split -> sl2cfoam-next reduced-Wigner / booster path

**Status:** `GENERAL_J_TO_L_IMPLEMENTATION_TARGET_IDENTIFIED / PHASE_AUDIT_PENDING / CAUSAL_VERTEX_PENDING`

## External analytic input

For the causal Lorentzian spinfoam split, the reduced Wigner matrix is decomposed as

`d = t^(+) + t^(-)`.

The 2026 Toller-matrix construction identifies the two terms with the positive/negative boost-frequency pieces selected by the Feynman `i epsilon` prescription.

For gamma-simple EPRL external representations,

`k = j`, `rho = gamma*j`.

The diagonal formulas `t_{jjm}^(+/-)` are useful at `l=j`, but they are **not sufficient for a numerical EPRL booster at Dl>0**.

## Why the general j -> l formulas are required

The existing `sl2cfoam-next` booster implementation calls

`sl2cfoam_dsmall(..., rho, two_j, two_j, two_l, two_p)`

with

- `k = j_external`,
- `j = j_external`,
- auxiliary `l >= j_external` generated by the booster shell sum.

Therefore a causal implementation following the same decomposition must evaluate the general Toller matrices

`t^(+/-)_(j l m)(rho,k; beta)`

for `l=j,j+1,...,j+Dl`. These are the general closed expressions of Eqs. (43)-(44) of Bianchi, Chen & Gamonal (2026), specialized only after the formula is evaluated to

`k=j_external`, `rho=gamma*j_external`.

At `Dl=0`, the diagonal gamma-simple expression is sufficient. At any nonzero booster cutoff it is not.

## Phase-convention requirement

The analytic Toller formulas are written in the Ruhl convention. The commonly used spinfoam convention differs from it by a rho-dependent unit phase

`Phi(rho;j,l)`.

It is not safe to guess whether the numerical library uses `Phi*d_Ruhl`, `conj(Phi)*d_Ruhl`, or an equivalent sign convention. MSQGR therefore treats the mapping as an empirical numerical question:

1. evaluate the unmodified upstream `sl2cfoam_dsmall` pointwise;
2. evaluate the Ruhl closed form at the same `(rho,k,j,l,m,beta)`;
3. compare explicit phase candidates;
4. accept a mapping only if one candidate gives a uniformly tiny residual over both diagonal and `l>j` cases;
5. apply exactly the same phase transformation to `t+` and `t-` before inserting them into the booster integrand.

Until this audit passes, no causal modification of `b4.c` or `b4_qagp.c` is trusted.

## sl2cfoam-next insertion point

The upstream code computes reduced Lorentzian Wigner matrices through

`sl2cfoam_dsmall(...)`

in `src/dsmall.c`. The booster integrations call this routine directly, including `src/b4.c` and `src/b4_qagp.c`.

The first causal implementation should therefore **not** post-project a completed scalar vertex. It should introduce a branch-aware reduced-matrix routine, schematically

`sl2cfoam_tsmall(branch, ...) -> t^(branch)`

with the same kinematic arguments as `sl2cfoam_dsmall`, and propagate the branch choice through the booster integrand before contraction into the vertex.

## Validation ladder

1. **General Python/mpmath oracle** — verify `t+ + t- = d_Ruhl` for `k=j`, `rho=gamma*j`, and `l=j..j+Dl`.
2. **Cancellation conditioning** — measure `K=(|t+|+|t-|)/|d|` to determine the extra precision required by the branch split.
3. **Phase-convention audit** — probe upstream `sl2cfoam_dsmall` and identify the exact Ruhl-to-sl2cfoam phase map on diagonal and `l>j` cases.
4. **C pointwise branch implementation** — compare compiled `t+`, `t-` against the phase-corrected high-precision oracle.
5. **Integrand additive test** — at identical quadrature nodes verify the ordinary booster integrand is reproduced when each reduced matrix is replaced by `t+ + t-`.
6. **Integrated booster additive test** — verify the corresponding integrated ordinary B4 tensor is recovered within controlled numerical error.
7. **Single causal booster sectors** — compute branch-resolved booster data and audit convergence with quadrature precision and shell cutoff.
8. **Causal vertex** — propagate the causal branch data through the Lorentzian EPRL vertex tensor.
9. **Same-realization coarse graining** — only then define the refinement/boundary map and evaluate CCI cross blocks `P_- iota P_+` and `P_+ iota P_-`.
