# DSIR -> Polygon Funnel v0.1

**Date:** 2026-09-13

**Status:** `INTERFACE_DRAFT / FROZEN_FIELDS_PENDING_ITER076N_T`

## Goal

The funnel converts the DSIR research state into a finite, testable downstream model-space contract. The polygon must not rediscover or silently modify the microscopic choices made upstream.

## Funnel stages

`SOURCE EVIDENCE`
`-> CARRIER`
`-> LOCAL CAUSAL AMPLITUDE`
`-> ORIENTATION / P3`
`-> DISTRIBUTIONAL K5 OBJECT`
`-> FINITE-SCALE COMPOSITION`
`-> RG/CCI INTERFACE`
`-> DSIR EXIT MANIFEST`
`-> POLYGON MODEL SPACE`

## Stage 1 — source evidence

Frozen inputs must identify primary literature, source equations and source-versus-derived scope. In particular, the published spectral `i epsilon` prescription remains immutable unless a downstream extension branch explicitly replaces the theory being tested.

## Stage 2 — carrier

Current carrier:

`Q=(K,o,j,i,x)`

with oriented causal labelled 2-complex `K`, causal/orientation data `o`, face representation-like labels `j`, edge intertwiner-like labels `i`, and optional local causal-sector label `x`.

The exit manifest must record the exact remaining equivalence/gauge relations; unresolved carrier ambiguities are not allowed to disappear into polygon code.

## Stage 3 — local causal amplitude

Minimum output:

- exact source-backed wedge kernel;
- local vertex integral/measure;
- causal branch data and reversal law;
- boundary-state interface;
- gluing/composition convention or a terminal missing-object record.

## Stage 4 — orientation / signed P3

The funnel has two admissible terminal outcomes.

### Native lane

A signed P3 is exported only if its orientation sign is source-provenanced by the exact amplitude.

### Native no-go lane

If the exact source does not contain/force the required sign character, the funnel exports:

- the unique unsigned complement/Hodge support already derived;
- the `{+H,-H}` line;
- the exact no-go/provenance result;
- the semiclassical Regge orientation result separately;
- `signed_P3.status = NO_GO_SOURCE_NATIVE`.

The polygon may then open an **extension** branch (for example a proper-vertex-style orientation projector), but that branch is not allowed to masquerade as source-native DSIR output.

## Stage 5 — distributional K5 object

The handoff must distinguish:

- pointwise finite-`epsilon` integrand;
- boundary-value distribution;
- absolute convergence;
- principal-value/finite-part constructions;
- extension ambiguity;
- correlated versus sequential limits.

No single word such as `finite` may collapse these categories.

## Stage 6 — finite-scale composition

The polygon receives explicit data types/functions for:

- boundary states;
- vertex amplitude application;
- gluing/composition;
- causal projectors when defined;
- normalization/measure conventions.

A missing component is exported as a typed blocker with a test, not as prose ambiguity.

## Stage 7 — RG/CCI interface

For every comparable boundary pair `b < b'`, the downstream interface reserves:

- `H_b`, `H_b'`;
- `iota_b'b`;
- `P_b^+`, `P_b^-` where defined;
- cylindrical residual;
- CCI residual `P_b'^+- iota_b'b - iota_b'b P_b^+-`;
- analytic/pole-class closure diagnostics.

This makes F9 a polygon-executable falsification test rather than a qualitative aspiration.

## Required output record for each field

Every funnel field must carry:

- `status`;
- `scope`;
- `definition` or `missing_object`;
- `provenance`;
- `authoritative_commit`;
- `authoritative_run` when computational;
- `artifact_digest` when computational;
- `dependencies`;
- `claim_locks`;
- `polygon_test` if not terminally solved.

## Polygon branches

### P0 — conservative source-native branch

Uses only source-native and derived-but-source-compatible DSIR outputs. No extra orientation projector, counterterm, fitted cancellation or preferred sequential distributional order may be added.

### P1 — explicit orientation-extension branch

May add a separately specified orientation/sector selector only if P0 terminates with source-native signed-P3 no-go. The new selector must have its own provenance and ablation test. P1 is a new model branch, not a repair of P0.

### P2 — alternative correlated-boundary extension

May test a mathematically canonical correlated extension only when the source boundary value is absent/non-unique. Any extra extension condition must be explicit and compared against the finite-`epsilon` source object.

## Exit condition

`DSIR_FUNNEL_READY=100%` iff every required output field has one allowed terminal status, all dependencies are acyclic and explicit, all computational claims point to reproducible runs/artifacts, and the polygon can instantiate P0 (plus any explicitly authorized extension branches) without asking DSIR to choose another hidden convention.
